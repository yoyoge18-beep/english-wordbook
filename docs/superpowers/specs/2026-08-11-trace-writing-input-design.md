# 따라 쓰기 입력칸 설계

- 작성일: 2026-08-11
- 대상: `wordbook.html` — 새 단어 소개 카드 (`drawIntro`)
- 상태: 승인됨

## 배경

새 단어 소개 카드는 단어·발음·품사·뜻·예문을 한 화면에 보여주고 「외웠어요」로 넘긴다.
눈으로 읽고 넘기는 것 외에 손으로 써 보는 단계가 없어서, 단어를 보면서 직접 입력해 볼
수 있는 칸을 요청받았다.

이 앱에는 이미 스펠링 시험(`drawSpell`)이 있다. 그쪽은 **한글 뜻만 보여주고 영어를 맞히는**
평가 화면이다. 이번 입력칸은 **단어가 보이는 채로 따라 쓰는** 연습이므로 목적이 다르고,
따라서 별개 기능으로 만든다.

## 결정

### 적용 범위

`drawIntro()` 카드에만 넣는다.

- `drawChoice`(4지선다)와 `drawSpell`(스펠링)은 이미 각자의 채점 방식이 있어 건드리지 않는다.
- `drawFlash`(카드 넘기기)는 뜻을 가린 상태가 핵심이라 따라 쓸 대상이 없다.

### 배치

예문 아래, 「외웠어요」 버튼 위. 입력칸은 `#answer` 안에 놓고 `#study-foot`은 버튼 전용으로 남긴다.

### 피드백 규칙

입력값과 정답을 각각 `trim().toLowerCase()` 한 뒤 비교한다.

| 입력 상태 | 표시 |
|---|---|
| 비어 있음 | 중립 (기본 테두리) |
| 정답의 앞부분과 일치 (`ach`, `achie`) | 중립 |
| 앞부분에서 어긋남 (`ache`) | `.wrong` — 빨간 테두리 |
| 완전히 일치 | `.right` — 초록 테두리 |

**접두사 일치 동안 중립으로 두는 것이 핵심이다.** 매 글자마다 완전 일치를 검사하면
`achieve`를 치는 도중 `a`, `ac`에서 계속 빨간불이 떠서 쓰는 내내 거슬린다.

### 통과 조건

「외웠어요」는 입력과 무관하게 항상 활성. 입력칸에서 Enter를 치면 「외웠어요」와 동일하게
채점 후 다음 카드로 넘어간다.

빈 칸으로도 넘어갈 수 있어야 한다 — 하루 20개를 빠르게 넘길 때 타이핑이 병목이 되면 안 된다.

### 자동 포커스 없음

카드가 뜰 때 커서를 자동으로 넣지 않는다. 자동 포커스를 넣으면 모바일에서 새 단어마다
키보드가 올라와 화면을 덮는다. 쓰고 싶을 때 탭해서 쓴다.

### 학습 기록과의 분리

따라 쓴 결과는 SRS 박스·정답률·통계 어디에도 반영하지 않고 저장하지도 않는다.
카드가 넘어가면 입력값은 사라진다. 채점이 아니라 손에 익히는 것이 목적이다.

이 분리 덕분에 기존 `grade()` / `advance()` 호출 경로를 수정할 필요가 없다.

## 구현

`wordbook.html` 단일 파일, `drawIntro()` 한 함수만 수정한다.

- 기존 `.spell` CSS 클래스와 `.right` / `.wrong` 상태를 그대로 재사용한다. 새 스타일은
  필요한 경우 여백 조정 정도로 최소화한다.
- 입력 이벤트에서 접두사 비교 → 클래스 토글.
- `keydown` 에서 Enter → 기존 「외웠어요」 핸들러와 같은 동작.

## 검증

이 프로젝트에는 테스트 하네스가 없다(단일 HTML 파일). 브라우저에서 직접 다음 네 가지를
확인한다.

1. 빈 칸 상태에서 「외웠어요」로 넘어가는가
2. 정답을 향해 타이핑하는 동안 빨간불이 뜨지 않는가
3. 철자가 어긋나면 빨간 테두리, 고쳐 쓰면 회복되는가
4. 완전히 일치하면 초록 테두리, Enter로 다음 카드로 넘어가는가
